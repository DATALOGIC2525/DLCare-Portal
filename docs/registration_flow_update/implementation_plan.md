# 実装計画: Googleフォーム形式の高度なテナント紐付け登録フロー

## 概要
現在の「発行ID方式」を廃止し、ユーザーが入力した会社情報（会社名、住所、電話、ドメイン）に基づいて既存テナントを自動特定し、紐付ける登録フローに変更します。

## ユーザー確認事項
> [!IMPORTANT]
> - 照合スコアが低い（どの会社とも一致しない）場合は登録を拒否する仕様で進めます。
> - 会社名の正規化では「株式会社」「㈱」「(株)」などは除外して比較します。
> - 既存のテナントデータに `address` や `phoneNumber` が入っていない場合、それらをDBに反映させる必要があります（今回は手動、または既存データから推測して更新します）。

## 1. データベースの更新 (`schema.prisma`)

### [MODIFY] [schema.prisma](file:///d:/%E3%82%BD%E3%83%95%E3%83%88%E9%96%8B%E7%99%BA/DLCare-Portal/prisma/schema.prisma)
- `Tenant` モデルに照合精度の向上のため、以下のフィールドを追加します。
  - `address`: String?（会社住所）
  - `phoneNumber`: String?（代表電話番号）
- `User` モデルにサービス申請用の情報を保持するためのフィールド（任意）または新規テーブル。

## 2. 照合ロジックの実装

### [NEW] `src/lib/tenant-matching.ts`
- 文字列正規化関数:
  - ㈱, (株), 株式会社, 有限会社 などの除去。
  - 全角・半角・大文字・小文字の統一。
  - スペースの除去。
- スコアリング関数:
  - **名前完全一致**: +5点
  - **名前部分一致**: +2点
  - **代表電話番号一致**: +3点
  - **メールドメイン一致**: +2点
  - **住所部分一致（都道府県・市区町村レベル）**: +1点
- **閾値**: 合計スコアが「5点以上」の場合に同一企業と判定（要調整）。
