# 所有システム（ソフト）情報の複数登録＆テーブル表示 実装計画

先ほどは1企業につき1つのソフト情報を登録する想定でしたが、いただいた画像のように**「1つの企業が複数のシステム（ソフト）を所有している状態」**を管理できるよう、データベースとUIを改修します。

## 課題と背景
現在の仕様では、`Tenant`（企業）テーブルに直接カラムを追加したため、複数ソフトの登録ができません。
画像にあるような詳細な一覧表（カテゴリ、商品名、総数、初回納入日、Verなど）を表現するため、専用のデータベーステーブルを新設し、1対多の構造に変更します。

## 💡 仕様に関する質問（User Review Required）

> [!IMPORTANT]
> **1. 管理する項目（カラム）について**
> 画像には以下の項目がありますが、これら**すべて**をデータベースの項目として用意してよろしいでしょうか？
> - カテゴリ（グレーの行：REAL4, Arris, NC, OA など）
> - 販売商品名
> - 総数
> - EC台数
> - 初回納入日（＝購入時期）
> - 最終更新日
> - Ver.
> 
> **2. CSVインポートについて**
> CSVは基本的に「1行＝1企業」となるため、複数のソフト情報を1行に詰め込むのは困難です。
> CSVインポート機能では**「とりあえず企業の枠（企業名、利用上限など）だけを一括で作成する」**形に戻し、ソフトの詳細情報は**登録後に画面から追加（または別途専用のシステム情報インポート機能を用意）**する方針でよろしいでしょうか？

## 提案する変更内容

### 1. データベースの再構築 (Database Schema)
先ほど `Tenant` に追加した簡易カラムを削除し、新しいモデル `TenantSoftware` を作成します。

#### [MODIFY] `prisma/schema.prisma`
- `Tenant` モデルから `softwareCount`, `purchaseDate` を削除。
- 新規モデル `TenantSoftware` を追加：
  - `id` (String)
  - `tenantId` (String, Relation)
  - `category` (String?)
  - `name` (String) : 販売商品名
  - `count` (Int) : 総数
  - `ecCount` (Int?) : EC台数
  - `purchaseDate` (String?) : 初回納入日
  - `lastUpdateDate` (String?) : 最終更新日
  - `version` (String?) : Ver.

### 2. 管理画面：UIの改修（テーブル表示）
マスター管理画面の登録済みユーザー一覧にて、いただいた画像のようなテーブルUIを実装します。

#### [MODIFY] `src/app/dashboard/admin/page.tsx`
- 既存の「基本情報」フォームからソフト情報を削除。
- 各企業のアコーディオン内に**「所有システム情報」テーブル**を新設。
- 画面上で「行を追加」ボタンを押し、商品名や本数を入力して保存できるUI（複数行の追加・編集・削除）を実装します。カテゴリごとにグループ化して表示するロジックも組み込みます。

### 3. Server Actionsの追加
ソフト情報の追加・更新・削除を行う専用のActionを作成します。

#### [MODIFY] `src/app/dashboard/admin/actions.ts`
- `addTenantSoftware`, `updateTenantSoftware`, `deleteTenantSoftware` 等のCRUD処理を実装。
- `updateTenantInfo` および CSVインポート用APIから古いカラムの処理を削除。

## 検証計画 (Verification Plan)
1. **マイグレーション**: 新しいテーブル構造が正常に適用されること。
2. **テーブルUIの動作**: マスター管理画面から、1つの企業に対して複数のソフト（REAL4, Arrisなど）を追加し、画像のようなテーブル形式で表示されること。
