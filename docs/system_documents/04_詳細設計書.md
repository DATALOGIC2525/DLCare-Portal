# DLCareポータルサイト 詳細設計書

## 0. 技術スタック
本プロジェクトは、主に以下の技術スタックを用いて開発されています。
- **メイン言語**: TypeScript (および JavaScript)
- **主要フレームワーク**: Next.js (App Router, React 19)
- **データベース ORM**: Prisma
- **データベース**: SQLite (開発環境)
- **スタイリング**: Tailwind CSS (v4)
- **認証**: NextAuth.js (v5 / auth.js)
- **主要ライブラリ**: lucide-react (アイコン), shadcn/ui (一部UIコンポーネント)

## 1. データベース物理設計 (Prisma Schema 抜粋とインデックス)
各テーブルの外部キーによる検索性能を担保するため、明示的なインデックス(`@@index`)を設定しています。

- **Tenant**: `id` (PK), `name`, `isActive`
- **User**: `id` (PK), `tenantId` (FK), `email` (Unique), `role`, `passwordHash`
  - `@@index([tenantId])`
- **Service**: `id` (PK), `name`, `groupLabel`, `iconName`
- **TenantServiceAccess**: `tenantId`, `serviceId`
  - `@@unique([tenantId, serviceId])` により複合インデックスとして機能。
  - テナント新規作成時(`createTenantWithId`)に、現在有効な全サービスに対するレコードを一括生成する（デフォルトON機能）。
- **PreIssuedId**: `id`, `tenantId`, `issuedId` (Unique), `isUsed`
  - `@@index([tenantId])`

## 2. コンポーネント設計
### 2.1 サーバーコンポーネント (Server Components)
原則として、データフェッチを行うページ層(`page.tsx`)やレイアウト(`layout.tsx`)はサーバーコンポーネントとして実装。
- **DashboardLayout**: 
  - `auth()` でセッション確認。
  - `Promise.all` を用いて、`user`、`activeUsersCount`、`unreadAnnouncementsCount` を並列取得しレンダリングブロックを軽減。

### 2.2 クライアントコンポーネント (Client Components)
インタラクティブな状態管理やHooks(`useState`, `usePathname`等)が必要なUI部品に適用。
- **NavItem (`src/components/nav-item.tsx`)**:
  - `usePathname` を利用したアクティブ判定 (`pathname === href`)。
  - アイコンのバンドルサイズ削減のため、動的インポートではなく `IconMap` を用いた明示的マッピングを採用。
- **DeleteTenantButton (`src/app/dashboard/admin/delete-tenant-button.tsx`)**:
  - `onClick` イベントでブラウザ標準の `confirm()` ダイアログを表示し、承認された場合のみサーバーアクション `deleteTenant` を呼び出す。

## 3. サーバーアクション (Server Actions) 設計
データ操作（作成・更新・削除）は `actions.ts` に集約し、各関数内で権限チェックを行います。

### 3.1 テナント・ユーザー管理 (`src/app/dashboard/admin/actions.ts`)
- **`createTenantWithId`**: 
  - トランザクション処理。Tenant作成 → 事前発行ID作成 → 管理者User作成 → 全Serviceのアクセス権作成 を一貫して行う。
- **`deleteTenant`**: 
  - システム管理アカウント（"株式会社データロジック (システム管理)"）が指定された場合は、例外(`Error`)をスローし削除をブロックする保護機構を実装。
- **`updateTenantServiceAccess`**: 
  - FormDataから選択された `serviceIds` を受け取り、既存の `TenantServiceAccess` を全削除後、新しくレコードを作成し直す手法を採用。

### 3.2 サービス表示フィルタリング (`src/app/dashboard/page.tsx`)
ダッシュボードでのサービス一覧取得ロジック：
1. テナントの `TenantServiceAccess` を取得。
2. もしアクセス設定レコードが1件も存在しない場合（古いテナント等）は、フォールバックとして「全サービス表示」とする。
3. レコードが存在する場合は、そのレコードに該当するサービスのみをフィルタリングして描画。

## 4. セキュリティ設計
- **認証**: NextAuth `session.user.role` をミドルウェアまたは各ページの先頭で検証。`SYSTEM_ADMIN` 以外のアクセスをリダイレクト。
- **XSS/CSRF対策**: Next.js と React の標準機能により自動サニタイズ。Server Actions でのCSRF保護。
