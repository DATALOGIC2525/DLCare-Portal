# DLCareポータルサイト 基本設計書

## 1. システム方式設計
### 1.1 全体アーキテクチャ
本システムは、Next.js 16 の App Router アーキテクチャを採用したフルスタックWebアプリケーションです。
- **フロントエンド**: React (Server Components および Client Components), Tailwind CSS, Lucide React (アイコン群)。
- **バックエンド**: Next.js サーバーアクション (Server Actions) によるAPIレスのデータ通信。
- **データベースアクセス**: Prisma ORMを使用。
- **データベースエンジン**: 開発環境はSQLite (`dev.db`)。
- **認証基盤**: NextAuth.js (`credentials` プロバイダーによる独自認証)。

### 1.2 画面レイアウト構成
- **共通レイアウト (DashboardLayout)**:
  - 左側に固定サイドバー（メニュー、利用状況メーター、ログアウトボタン）。
  - サイドバーは現在のパスに完全一致(`pathname === href`)した場合にハイライト表示を行う。
  - 中央右側にメインコンテンツエリア。
- **レスポンシブデザイン**:
  - CSS Grid および Flexbox を多用し、モダンなカード型UI（グラスモーフィズム、シャドウ効果）を実装。

## 2. 画面遷移設計
1. **ログイン画面 (`/login`)**
   - 認証成功でダッシュボードへ遷移。
   - 開発環境(`NODE_ENV === 'development'`)限定で、デモ用アカウントのクイック入力ボタンを表示。
2. **ダッシュボード画面 (`/dashboard`)**
   - 所属テナントに紐づくサービス一覧（アイコン付きカード）を表示。
3. **マイページ (`/dashboard/mypage`)**
   - パスワード変更、基本プロフィール更新フォーム。
4. **システム管理画面 (`/dashboard/admin/*`)** ※システム管理者のみ
   - `/dashboard/admin`: マスター管理（テナント追加・削除、サービスアクセス制限、認証情報設定）。
   - `/dashboard/admin/users`: 登録ユーザー・メルマガ配信リスト（テナントごとの担当者一覧。マスターアカウントは非表示）。
   - `/dashboard/admin/services`: サービス・バリアント設定画面。
   - `/dashboard/admin/announcements`: お知らせ配信管理画面。

## 3. データモデリング（基本構造）
システムは以下の主要なエンティティを中心に構成されます。
- **Tenant (テナント)**: 顧客企業情報。利用上限(`userLimit`)、保守情報(`maintenanceId`等)を持つ。
- **User (ユーザー)**: 認証と権限(`role`)を持つ個人アカウント。必ずいずれかのTenantに所属。
- **Service (サービス)**: ダッシュボードに表示されるアプリケーションやリンクの定義。
- **ServiceVariant (バリアント)**: 特定のサービスに関連するダウンロードリンクなどのバリエーション。
- **TenantServiceAccess / TenantVariantAccess**: テナントとサービス/バリアントの多対多関係を結ぶアクセス権テーブル。
- **TenantCredential / UserCredential**: 外部サービス（く～chat等）にログインするためのID/パスワード保存テーブル。
- **Announcement / UserAnnouncementRead**: 全体へのお知らせと、その既読トラッキング。

## 4. 外部インターフェース設計
### 4.1 外部システムへの動的リンク
- サービスオブジェクトの `url` カラムに保存されたリンクを `href` に設定し、`target="_blank"` で別タブとして開く。
- Kasanare AI (く～chat) や Uliza (オンラインセミナー) へのシームレスな遷移を想定。

### 4.2 CSVエクスポート
- `/api/admin/export-users` などのAPIルートを通じて、動的にCSVデータを生成しダウンロードさせる。主にメルマガ配信用リストとして活用。
